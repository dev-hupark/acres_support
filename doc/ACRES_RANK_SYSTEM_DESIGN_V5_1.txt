주의: S05의 개인정보 삭제·비식별화는 방향만 확정되었고, 보존 항목/기간/실제 익명화 기법은 운영·법률 검토 대상이다.

1. 확정 업무 정책: 회원 및 캐릭터 (A)
============================================================================
A01 파티 생성/신청 전 게임 캐릭터 등록 필수.
A02 캐릭터를 가진 회원은 대표 캐릭터 정확히 1개; 변경 가능. 대표 변경은 기존 파티 신청/참여를 변경하지 않음.
A03 파티 참여 중인 캐릭터 삭제 제한. 게임 UID 수정 허용(전역 중복 검증); 내부 CHARACTER PK는 불변.
A04 계정 탈퇴 전 본인 소유 파티 해체, 소유 연맹 위임 또는 해체 필수.
A05 최초 Google OAuth 회원가입 과정에서 대표 캐릭터명과 게임 UID 필수. 회원+첫 캐릭터 생성은 단일 트랜잭션.
G04 Supabase 인증 사용자 1개당 사이트 회원 1개. G05 화면 표시 이름은 현재 대표 캐릭터명.
회원 정보에는 불필요한 실명·전화번호·주소를 별도로 수집하지 않음. OAuth 인증정보 처리 및 탈퇴 데이터 처리 정책은 별도 준수.

2. 확정 업무 정책: 파티 모집·신청 (B, H, R, S)
============================================================================
파티는 파티명·출발일·신청 마감 일시·공개 범위(일반/연맹 전용)를 갖는다. 공통 랭크 시작일과 독립.
B01 출발 당일에도 파티 생성 가능. R02 신청 마감은 출발일 이후로도 설정 가능. B03 마감 날짜·시각은 직접 지정. B02 출발 당일 마감 허용.
R07 신청 마감 수정은 생성자만; 기존 신청·승인 상태 유지. H07 마감 후 신규/재신청 차단, 기존 PENDING의 승인/반려는 기한 제한 없음(B04).
F06 출발일이 지난 파티는 모집 목록에서 제외, 기존 참여자는 내 파티에서 조회. S01 출발일 이후에도 상세 화면·직접 링크로 마감 전 신청 가능.
파티 신청은 회원 단위로 수행. 신청 단계에서 캐릭터를 선택하지 않는다. 회원당 파티별 현재 신청 행 1건. 신청 메모 선택 입력.
B08 취소·반려 후 재신청 시 기존 신청 행 재사용; 과거 신청 상태를 별도 기록하지 않음. R10 자발적 파티 탈퇴 후 마감 전 재신청 가능(동일 행 재사용).
파티 생성자는 생성과 동시에 승인 회원/불변 소유자가 되며, R03 생성 시 본인 캐릭터 1개 이상 직접 선택. B05 생성자는 여러 캐릭터로 참여 가능. B06/R11 생성자는 항상 승인된 참여 캐릭터 최소 1개 유지; 마지막 캐릭터 제외는 차단.
일반 신청 회원은 승인 후 본인 캐릭터를 직접 선택(H01); 승인 직후 캐릭터 0개 허용(H08). 추가/교체는 출발 후에도 허용(B10,R08). 동일 회원은 복수 캐릭터 참여 가능. 동일 캐릭터의 여러 파티 참여 허용(R09), 단 동일 파티에서 동일 캐릭터 중복 참여 불가.
회원 강퇴는 회원 단위로 모든 참여 캐릭터 제외. B07 기본적으로 강퇴 후 재신청 차단, H09/R01 생성자·추가 관리자·ADMIN이 차단 해제 가능; 해제 후 마감 전 재신청 가능.
C07 회원 강퇴와 개별 캐릭터 제외는 별도 기능. R04 관리자가 제외한 캐릭터 재등록에는 관리자 승인 필요. S02 동일 참여 행을 PENDING_REAPPROVAL로 재사용. S03 본인이 제외한 캐릭터는 즉시 재등록 가능.
S04 회원 자발적 탈퇴 시 모든 참여 캐릭터 제외, 병종·일정 삭제. H03 개별 캐릭터 제외/교체 시 해당 파티 병종·일정 삭제(다른 파티 정보 영향 없음).
B09 파티 출발 후에도 해체 가능. G03 해체 후 복구 불가.

3. 확정 업무 정책: 파티 관리자·권한 (C)
============================================================================
파티 OWNER는 생성자로 고정, 소유권 이전 불가. 추가 관리자는 승인 회원에 부여하는 역할이며 캐릭터에 부여하지 않음(C04).
C01 추가 관리자 수 제한 없음. C02 추가 관리자 지정/해제는 생성자만(ADMIN은 시스템 예외 권한). C03 추가 관리자는 다른 추가 관리자를 강퇴할 수 없음; 생성자/ADMIN 가능.
C05 관리자가 파티에서 탈퇴/강퇴되면 관리자 권한 즉시 해제.
생성자: 승인·반려, 일반 회원 강퇴, 다른 관리자 강퇴, 공지 전체 관리, 관리자 지정·해제, 파티 해체, 개별 캐릭터 제외.
추가 관리자: 승인·반려, 일반 회원 강퇴, 공지 전체 관리, 개별 캐릭터 제외, 강퇴 재신청 차단 해제. 관리자 지정·해제/다른 관리자 강퇴/파티 해체 불가.
ADMIN: 전체 파티 관리 기능 수행. C06 파티 생성자 강퇴 불가, 대신 파티 해체 가능. 관리자 강퇴 및 관리자 지정/해제 가능.
승인된 파티원은 다른 승인 회원과 그 참여 캐릭터·일정 조회 가능. 비승인 회원은 타인의 참여 상세를 볼 수 없음.


============================================================================
4. 확정 업무 정책: 캐릭터별 병종·전쟁 일정 (E, H)
============================================================================
참여 캐릭터마다 해당 파티에서 병종을 독립 설정(H02). 병종은 선택 입력: 0/1/2개 가능; 두 슬롯 모두 NULL 가능(E02). 두 슬롯 동일 병종 중복 금지(E01).
예: 한 회원이 한 파티에 2개 캐릭터 참여하면 병종 최대 4개 선택 가능. 회원 전체에 별도 총량 상한 없음.
병종 변경 권한은 캐릭터 소유 회원 및 ADMIN만(E03). 출발일 이후에도 변경 가능. 병종은 캐릭터의 전역 속성이 아니라 파티 참여 캐릭터의 속성.
전쟁 안내 시간은 한국시간 매일 20:00~24:00. 일정 대상 날짜는 파티 출발일 포함 12개 날짜(E08); 파티별 실제 종료일/조기 종료는 추적하지 않음.
일정은 참여 캐릭터별 관리(E10). 해당 날짜 일정 행이 없으면 FULL(E06). 예외는 ABSENT(메모 선택, E05)와 PARTIAL(메모 필수, E04)만 기록. PARTIAL에는 시작·종료 시각 필드 없음.
출발 전 미래 날짜 입력 가능(E07). 지난 날짜도 수정 가능(E09). 일정 수정은 캐릭터 소유 회원 및 ADMIN, 승인된 파티원에게 조회 허용.
캐릭터 제외/교체 시 해당 파티의 병종·일정 제거(H03). 재등록·재승인 시 새로 입력.

5. 확정 업무 정책: 연맹 (D, H, R)
============================================================================
연맹 창설은 연맹명만 입력, 창설자가 OWNER. 활성 연맹 간 연맹명 중복 금지(D01); 해체된 이름 재사용 가능. 회원의 복수 연맹 창설·가입 허용(D02).
연맹은 OWNER 1명, DEPUTY 여러 명, MEMBER로 구성. 가입 신청 승인제. 자발적 탈퇴 후 재가입은 재신청·재승인 필요(D06). 강퇴 시 재신청 차단, OWNER가 차단 해제하면 재신청 가능(D05).
연맹장: 가입 승인/반려, 강퇴, 역할 변경, 공지 전체 관리, 위임, 해체. 부연맹장: 가입 승인/반려, 공지 전체 작성·수정·삭제(H06). 다른 부연맹장 강퇴·등급 변경 불가(D07). 시스템 ADMIN은 운영 권한 보유.
연맹장은 위임 또는 해체 후 탈퇴 가능(D04). 위임 시 이전 연맹장 역할은 MEMBER 또는 DEPUTY 중 선택(D03). 대상 회원 수락 후 위임 완료(H05); 수락 전 요청 취소 및 대상 거절 가능(R05). 연맹당 대기 위임 요청 최대 1건(R06).
연맹 공지는 현재 승인된 연맹원만 조회. 작성 권한은 OWNER/DEPUTY(D12). 공지 상단 고정 제공(F04).
연맹 전용 파티는 해당 연맹의 모든 회원이 생성 가능(D08). 신청·승인·참여 캐릭터 추가·일정 조회 등 주요 작업에서 현재 연맹 회원 자격 확인(H10). 전용 파티 관리자도 연맹 회원이어야 함(D11).
연맹 탈퇴·강퇴 시 연결된 전용 파티 참여 자격 즉시 제거(D09). 해당 회원이 전용 파티 생성자이면 그 파티는 자동 해체(H04). 연맹 해체 시 연결된 전용 파티 모두 해체(D10).

6. 확정 업무 정책: 공지·목록·공통 랭크 (F, G)
============================================================================
F01 파티 공지 조회는 승인 회원만. F02 파티 생성자/추가 관리자는 모든 파티 공지 작성·수정·삭제 가능. ADMIN 예외 관리 가능.
F03 공지 읽음 확인 없음. F04 파티·연맹 공지 상단 고정. F05 제목/본문 텍스트만; 파일·이미지 첨부 없음.
F06 출발일 지난 파티는 모집 목록에서 제외; 내 파티에서 조회. F07 해체 파티·연맹은 일반 목록에서 제외하고 기존 참여자의 내 목록에서 해체 상태 표시.
F08 파티 모집 회원 수 제한 없음. F09 연맹 가입 인원 제한 없음.
공통 랭크 시작일은 파티와 독립적인 달력 안내 정보. 보통 3일 간격이나 자동 생성하지 않음(G08). 시스템 ADMIN만 수동 등록·수정·삭제(G07). 파티 시작일은 공통 랭크 날짜에 종속되지 않음.


============================================================================
7. 데이터 보관·삭제·보안 (G, R12, S05)
============================================================================
G01 핵심 업무 데이터는 논리 삭제, 임시/부속 데이터는 물리 삭제를 기본 원칙으로 함. G02 현재 신청 상태 행 유지; 취소·반려·강퇴 시 과거 버전은 별도 보존하지 않음. G03 해체 복구 불가.
G06 ADMIN 권한은 DB 또는 서버 운영 절차로 지정. G09 별도 업무 감사 로그 테이블 없음. 단 인증/운영 보안 로그는 별개이며 법적·보안 의무를 무시하는 의미가 아님.
R12/S05 계정 탈퇴 시 개인 식별 정보 삭제·비식별화, 재식별할 수 없는 비개인 참여 관계만 필요 범위에서 보존. 캐릭터명·게임 UID·OAuth UID·작성자 연결 등 식별 가능성 검토. 단순 해시·가명화가 자동으로 익명화가 되지는 않음.
실제 개인정보 보존 기간·삭제 절차·FK 처리 방식은 물리 DDL 전 별도 확정해야 함. 탈퇴 전 본인 소유 파티 해체 및 연맹 소유권 위임/해체를 검증(A04).

8. 권장 논리 데이터 모델 (물리 테이블명 미확정)
============================================================================
[회원/캐릭터]
ACRES_USER(USER_SEQ PK, SUPABASE_AUTH_UID UNIQUE, ROLE_CD, STATUS_CD, MAIN_CHARACTER_SEQ nullable, REG_DT, MOD_DT)
ACRES_CHARACTER(CHARACTER_SEQ PK, USER_SEQ FK, GAME_CHAR_UID UNIQUE, CHARACTER_NAME, STATUS_CD, REG_DT, MOD_DT)
- 회원이 캐릭터를 소유하면 MAIN_CHARACTER_SEQ가 반드시 소유 캐릭터를 가리키도록 서비스 트랜잭션 검증. 최초 가입 시 사용자+첫 캐릭터+대표 지정 원자적 처리.

[파티]
ACRES_PARTY(PARTY_SEQ PK, OWNER_USER_SEQ FK, PARTY_NAME, DEPARTURE_DATE, APPLY_DEADLINE_AT, SCOPE_CD, ALLIANCE_SEQ nullable FK, STATUS_CD, REG_DT, MOD_DT)
ACRES_PARTY_MEMBER(PARTY_MEMBER_SEQ PK, PARTY_SEQ FK, USER_SEQ FK, APPLY_STATUS_CD, IS_MANAGER_YN, APPLY_MEMO, BLOCKED_YN, REG_DT, MOD_DT, UNIQUE(PARTY_SEQ,USER_SEQ))
ACRES_PARTY_CHARACTER(PARTY_CHARACTER_SEQ PK, PARTY_MEMBER_SEQ FK, CHARACTER_SEQ FK, PARTICIPATION_STATUS_CD, TROOP_SLOT1_CD nullable, TROOP_SLOT2_CD nullable, REG_DT, MOD_DT)
- 동일 파티+캐릭터 UNIQUE는 PARTY_MEMBER의 PARTY_SEQ를 이용한 애플리케이션 검증 또는 PARTY_CHARACTER에 PARTY_SEQ를 함께 보유하고 복합 FK/UNIQUE를 적용하는 방식 중 선택. UNIQUE(PARTY_MEMBER_SEQ,CHARACTER_SEQ) 필수.
- TROOP_SLOT1_CD <> TROOP_SLOT2_CD (두 값 모두 존재하는 경우), FK는 병종 코드 마스터에 연결.
ACRES_PARTY_CHARACTER_SCHEDULE(SCHEDULE_SEQ PK, PARTY_CHARACTER_SEQ FK, WAR_DATE, STATUS_CD[ABSENT/PARTIAL], MEMO nullable, UNIQUE(PARTY_CHARACTER_SEQ,WAR_DATE))
ACRES_PARTY_NOTICE(NOTICE_SEQ PK, PARTY_SEQ FK, AUTHOR_USER_SEQ FK nullable, TITLE, BODY, PINNED_YN, STATUS_CD, REG_DT, MOD_DT)

[연맹]
ACRES_ALLIANCE(ALLIANCE_SEQ PK, ALLIANCE_NAME, OWNER_USER_SEQ FK, STATUS_CD, REG_DT, MOD_DT)
ACRES_ALLIANCE_MEMBER(ALLIANCE_MEMBER_SEQ PK, ALLIANCE_SEQ FK, USER_SEQ FK, JOIN_STATUS_CD, ROLE_CD[OWNER/DEPUTY/MEMBER], BLOCKED_YN, REG_DT, MOD_DT, UNIQUE(ALLIANCE_SEQ,USER_SEQ))
ACRES_ALLIANCE_OWNER_TRANSFER(TRANSFER_SEQ PK, ALLIANCE_SEQ FK, FROM_USER_SEQ FK, TO_USER_SEQ FK, FROM_NEXT_ROLE_CD, STATUS_CD[PENDING/ACCEPTED/REJECTED/CANCELED], REG_DT, MOD_DT)
- 위임 요청은 변경 이력이 아닌 현재 요청으로 관리; 완료·취소·거절 후 행 재사용/정리 방식은 물리 설계에서 결정. 연맹당 PENDING 1건 제한.
ACRES_ALLIANCE_NOTICE(NOTICE_SEQ PK, ALLIANCE_SEQ FK, AUTHOR_USER_SEQ FK nullable, TITLE, BODY, PINNED_YN, STATUS_CD, REG_DT, MOD_DT)

[공통 랭크]
ACRES_RANK_CALENDAR(RANK_DATE_SEQ PK, RANK_START_DATE, TITLE nullable, STATUS_CD, REG_DT, MOD_DT)

인덱스 후보: PARTY(STATUS_CD,DEPARTURE_DATE), PARTY_MEMBER(USER_SEQ,APPLY_STATUS_CD), PARTY_CHARACTER(CHARACTER_SEQ), SCHEDULE(PARTY_CHARACTER_SEQ,WAR_DATE), ALLIANCE_MEMBER(USER_SEQ,JOIN_STATUS_CD), RANK_CALENDAR(RANK_START_DATE).
Oracle 활성 연맹명 유일성은 CASE WHEN STATUS_CD='ACTIVE' THEN NORMALIZED_NAME END 함수 기반 UNIQUE 인덱스 등으로 구현 가능. 대소문자/공백 정규화 규칙은 DDL 단계 결정.
참여 관계·공지 작성자 FK는 계정 탈퇴 비식별화 정책에 맞춰 NULL/익명 주체/집계 분리 중 선택해야 함. 삭제 연쇄(CASCADE)를 무분별하게 사용하지 않음.

9. 상태 모델 및 전이
============================================================================
[파티] ACTIVE -> DISSOLVED (역전이 없음). 출발일 경과는 파티 해체 상태와 별개.
[회원 파티 신청] PENDING -> APPROVED 또는 REJECTED; PENDING -> CANCELED; APPROVED -> LEFT 또는 KICKED; REJECTED/CANCELED/LEFT -> PENDING(마감 전 재신청); KICKED -> 차단 해제 후 PENDING(마감 전). 회원당 동일 행 재사용.
[파티 참여 캐릭터] APPROVED -> REMOVED_BY_USER 또는 EXCLUDED_BY_ADMIN; REMOVED_BY_USER -> APPROVED(즉시); EXCLUDED_BY_ADMIN -> PENDING_REAPPROVAL -> APPROVED 또는 EXCLUDED_BY_ADMIN. 제외 시 병종 NULL, 일정 삭제. 회원 상태가 APPROVED가 아니면 참여 불가.
[연맹 가입] PENDING -> APPROVED/REJECTED/CANCELED; APPROVED -> LEFT/KICKED; KICKED는 차단 해제 전 신청 불가.
[연맹장 위임] PENDING -> ACCEPTED/REJECTED/CANCELED. ACCEPTED 시 새 OWNER 지정, 기존 OWNER 선택 등급 반영을 하나의 트랜잭션으로 수행.
[공지] ACTIVE -> DELETED (논리 삭제 권장).
[전쟁 일정] ABSENT 또는 PARTIAL만 저장. FULL 선택 시 행 삭제. PARTIAL MEMO는 trim 후 비어 있지 않아야 함.

상태 코드와 각 전이의 DB 검증/잠금은 서비스 레이어 및 제약으로 보장. 상태명은 권장 코드로 최종 코드 마스터 확정 전 변경 가능.

12. 주요 트랜잭션·검증
============================================================================
T01 최초 가입: auth UID 중복 방지 -> USER 생성 -> CHARACTER 생성 -> 대표 지정 -> COMMIT.
T02 파티 생성: 마감 일시 검증 -> PARTY 생성 -> OWNER 회원 승인 행 생성 -> 선택 캐릭터(1개 이상) 참여 생성 -> COMMIT.
T03 파티 신청: PARTY 활성, KST 마감, 회원 캐릭터 보유, 연맹 자격, 강퇴 차단 검증 -> PARTY_MEMBER 잠금/재사용 -> PENDING -> COMMIT.
T04 승인/반려: 관리자 권한 및 대상 PENDING 확인 -> 현재 상태 갱신. 마감 후에도 처리 가능.
T05 캐릭터 등록/교체: 회원 승인 상태, 캐릭터 소유권, 동일 파티 중복, 전용 파티 자격, OWNER 최소 1개 보장. 교체는 새 참여 등록과 기존 참여 제거를 원자적으로 처리.
T06 관리자 캐릭터 제외: 마지막 OWNER 캐릭터 차단, 해당 참여 상태 EXCLUDED_BY_ADMIN, 병종 NULL 및 일정 삭제. 재등록은 PENDING_REAPPROVAL, 관리자 승인 필요.
T07 회원 탈퇴/강퇴: 해당 회원 참여 캐릭터 일괄 제외, 병종/일정 삭제, 추가 관리자 권한 회수, 회원 상태 변경. 연맹 전용 파티는 연맹 자격과 함께 처리.
T08 연맹 회원 탈퇴/강퇴: 연결 전용 파티 참여 자격 제거. 회원이 해당 전용 파티 OWNER이면 파티 자동 해체. 실패 시 전체 롤백; 여러 파티를 일정 순서로 잠금.
T09 연맹 해체: 연맹 DISSOLVED + 모든 연결 전용 파티 DISSOLVED + 신규 활동 차단. 기존 참여 관계는 조회 목적에 맞게 보존.
T10 연맹장 위임: PENDING 1건, 대상 현재 승인 회원 확인 -> 수락 시 OWNER 및 역할 변경 원자적 처리.
T11 일정 저장: 참여 캐릭터 승인, 소유권/ADMIN, WAR_DATE가 출발일~출발일+11일 사이, PARTIAL 메모 필수, 날짜별 1행 검증.
T12 계정 탈퇴: 본인 소유 파티/연맹 선행 정리 검증, Supabase 계정 처리와 업무 DB의 개인정보 삭제·비식별화 간 장애 복구 설계 필요(분산 트랜잭션 가정 금지).

 -> 파티 + OWNER 승인 회원 + 선택 캐릭터 등록(단일 트랜잭션)
 -> PT-003 파티 상세 -> 참여 캐릭터 병종/일정 설정(선택)
주의: 출발일 당일 생성 가능, 마감일은 출발일 이후도 가능. 파티 생성자의 참여 캐릭터 최소 1개는 항상 유지.

[FL-03 파티 신청·승인·참여]
PT-001 모집 목록 또는 직접 상세 링크 -> PT-003 기본 정보 확인
 -> (로그인/캐릭터 보유/연맹 자격/마감/차단 상태 검증)
 -> 회원 단위 신청 + 선택 메모 -> PARTY_MEMBER=PENDING
 -> 생성자/추가 관리자/ADMIN의 PT-007 승인·반려
   ├─ 승인: PARTY_MEMBER=APPROVED -> PT-004 본인 캐릭터 0개 이상 추가
   │         -> 캐릭터별 병종 0~2개 선택 -> PT-005 12일 일정 예외 입력
   └─ 반려: REJECTED -> 마감 전 기존 신청 행 재사용 재신청 가능
신청 시 캐릭터를 고르지 않으며 승인 후에도 캐릭터 0개인 일반 회원은 정상 상태.
마감 후에는 신규/재신청 불가. 이미 PENDING이면 마감/출발 후에도 승인·반려 가능.
출발일 지난 파티는 모집 목록에 나타나지 않으나 상세 URL에서 마감 전 신청 가능.

[FL-04 캐릭터 변경·제외·재등록]
PT-004 참여 캐릭터 선택
  ├─ 본인 제외: REMOVED_BY_USER -> 해당 파티 병종 NULL/일정 삭제
  │            -> 재등록 즉시 APPROVED (회원 승인 상태/연맹 자격 등 검증)
  └─ 관리자 제외: EXCLUDED_BY_ADMIN -> 해당 파티 병종 NULL/일정 삭제
               -> 본인 재등록 요청: PENDING_REAPPROVAL
               -> 파티 관리자 재승인 시 APPROVED; 거절 시 EXCLUDED_BY_ADMIN(제안)
파티 생성자의 마지막 승인 캐릭터는 제외 불가; 다른 캐릭터 추가 후 제외.
동일 캐릭터는 다른 파티에서 독립 참여 가능. 한 파티에서 중복 참여 불가.

[FL-05 파티 탈퇴·강퇴·해체]
일반 회원 자발 탈퇴 -> PARTY_MEMBER=LEFT, 관리자 권한 회수,
 -> 참여 캐릭터 전체 제외, 병종/일정 삭제 -> 마감 전 재신청 가능.
관리자 강퇴 -> PARTY_MEMBER=KICKED, BLOCKED_YN=Y, 캐릭터/일정 정리
 -> 생성자·추가 관리자·ADMIN 차단 해제 -> 마감 전 재신청 가능.
생성자 해체 또는 ADMIN 해체 -> PARTY=DISSOLVED -> 신규 변경 작업 중지
 -> 이전 참여자는 PT-008에서 해체 상태 확인. 복구 불가.
파티 생성자는 강퇴 불가(ADMIN 포함).

[FL-06 연맹 가입·운영]
AL-001 목록 -> AL-003 상세 -> 가입 신청 -> PENDING
 -> 연맹장/부연맹장/ADMIN 승인 -> 연맹원으로 활동
 -> 연맹 공지 열람/연맹 전용 파티 신청·생성 가능
탈퇴: 재신청·재승인 필요. 강퇴: 연맹장이 차단 해제하기 전 재신청 불가.
연맹 탈퇴·강퇴 -> 소속 연맹 전용 파티 참여 즉시 해제
 -> 탈퇴자가 연맹 전용 파티 생성자라면 해당 파티 자동 해체.
연맹 해체 -> 연결된 전용 파티 모두 해체.

[FL-07 연맹장 위임]
연맹장 -> AL-006 위임 대상 현재 승인 회원 선택 + 본인 후속 등급 선택
 -> 위임 PENDING (연맹당 1건) -> 대상 회원에게 수락/거절 선택 제공
  ├─ 수락: 새 OWNER 지정, 기존 OWNER는 MEMBER/DEPUTY로 변경(원자적)
  ├─ 거절: 기존 OWNER 유지
  └─ 기존 OWNER 취소: 기존 OWNER 유지
위임 수락 전에는 기존 연맹장이 탈퇴할 수 없음.

[FL-08 공통 랭크 일정]
ADMIN -> AD-002 시작일 수동 등록/수정/삭제 -> RC-001 달력 표시
파티 출발일과 랭크 시작일은 연동되지 않으며 자동 생성하지 않음.

[FL-09 계정 탈퇴]
MY-003 탈퇴 요청 -> 본인 소유 활성 파티 존재/소유 연맹 존재 확인
 -> 남아 있으면 해체/위임 안내 후 탈퇴 차단
 -> 조건 충족 시 개인정보 삭제·비식별화 + 인증 계정 처리
 -> 비개인 참여 관계만 보존. 상세 처리·보존 기간은 운영/법률 확정 필요.

[공통 예외 흐름]
- 로그인 만료: 인증 화면 이동 후 원래 화면 복귀(제안), 변경 요청은 재인증 후 재실행.
- 권한 상실(강퇴/연맹 탈퇴/관리자 해제): 즉시 편집·비공개 조회 중지, 서버 403 처리.
- 파티 해체/마감 동시 발생: 서버의 현재 상태·시간을 기준으로 거부, 화면 새로고침 안내.
- 중복 클릭/동시 신청: DB UNIQUE 및 트랜잭션 잠금으로 단일 상태 보장.


============================================================================
16. 메뉴별 상세 화면 기능 명세 (화면 ID / 기능 / 권한 / 검증)
============================================================================
[AU-001 로그인]
목적: Google OAuth 인증 및 회원 존재 여부 확인.
구성: 서비스 안내, Google 로그인, 공개 화면 이동(공개 접근 허용 시).
동작: 인증 성공 시 기존 회원은 HM-001, 신규 회원은 AU-002.
검증: Supabase auth UID 기준 회원 연결; 이메일을 고유 식별자로 사용하지 않음.

[AU-002 최초 캐릭터 등록]
목적: 사이트 회원과 최초 대표 캐릭터 동시 등록.
입력: 캐릭터명(필수), 게임 UID(필수).
버튼: 중복 확인(선택 UI), 등록 완료.
검증: 게임 UID 전역 유일, 입력값 유효성, 중복 회원 가입 차단.
완료: HM-001 이동. 실패 시 입력 유지, 원자적 롤백.

[HM-001 홈/대시보드]
목적: 로그인 상태와 핵심 활동에 대한 진입점 제공.
표시: 대표 캐릭터명, 내 파티 요약, 내 연맹 요약, 다가오는 공통 랭크 일정, 접근 가능한 공지 요약.
이동: 내 파티 PT-008, 내 연맹 AL-007, 랭크 달력 RC-001, 내 캐릭터 MY-002.
권한: 개인 요약은 본인만, 공지는 소속 자격 검증 후 표시.
참고: 요약 카드 수·정렬·기간은 화면 설계 제안.

[MY-001 내 정보]
목적: 회원 상태 및 대표 캐릭터 정보 확인.
표시: 대표 캐릭터명, 보유 캐릭터 수, 참여 파티/연맹 바로가기.
버튼: 캐릭터 관리, 계정 탈퇴.
권한: 본인.

[MY-002 내 캐릭터]
목적: 보유 캐릭터 등록·수정·삭제 및 대표 지정.
표시: 캐릭터명, 게임 UID, 대표 여부, 삭제 가능 여부.
버튼: 캐릭터 추가, 수정(UID 포함), 삭제, 대표 지정.
검증: UID 전역 중복 금지; 파티 참여 중 삭제 불가; 캐릭터 보유 시 대표 1개 유지.
대표 변경은 기존 파티 신청/참여를 변경하지 않음.

[MY-003 계정 탈퇴]
목적: 회원 탈퇴 및 선행 조치 안내.
표시: 소유 파티/연맹의 미정리 항목, 개인정보 처리 안내.
버튼: 소유 파티 이동, 연맹 위임/해체 이동, 탈퇴 확인.
검증: 소유 활성 파티·연맹 존재 시 탈퇴 차단. S05 적용.

[PT-001 파티 모집 목록]
목적: 신규 참여 가능한 파티 탐색.
조회: 활성 파티 중 출발일이 오늘 또는 미래인 목록; 연맹 전용은 자격에 따라 제한(제안).
표시: 파티명, 출발일, 신청 마감, 일반/연맹 전용 구분, 모집 상태.
검색/필터(제안): 파티명, 출발일, 모집 상태, 공개 범위, 연맹.
버튼: 상세 보기, 파티 생성.
검증: 목록에서 숨겨진 과거 출발 파티도 상세 URL은 접근 가능(S01).

[PT-002 파티 생성]
목적: 파티 기본 정보 및 최초 참여 캐릭터 등록.
입력: 파티명(필수), 출발일(필수), 신청 마감 일시(필수), 공개 범위(필수), 연맹(전용 시 필수), 내 캐릭터 선택(1개 이상).
버튼: 생성, 취소.
검증: 출발 당일 생성 가능; 마감일은 출발일 이후 가능; 연맹 전용 생성 시 현재 연맹 회원 확인.
처리: PARTY+OWNER PARTY_MEMBER+선택 PARTY_CHARACTER 원자적 저장.
완료: PT-003 이동.

[PT-003 파티 상세 / PT-003-A 기본 정보·신청]
목적: 파티 기본 정보 확인 및 회원 단위 신청.
표시: 파티명, 출발일, 마감 시각, 공개 범위/연맹, 상태, 내 신청 상태.
버튼: 신청, 신청 취소(대기 중), 재신청(허용 상태), 내 파티 이동, 관리자용 마감 수정(생성자만), 해체(생성자/ADMIN).
신청 입력: 메모(선택), 캐릭터 선택 없음.
검증: 로그인/캐릭터 보유/마감/차단/연맹 자격/파티 활성 상태.
신청 마감 후 PENDING 승인·반려는 가능. 상세 접근은 출발 후에도 가능.

[PT-003-B 파티 참여 현황]
목적: 승인된 회원·캐릭터·전쟁 일정 공유 조회.
표시: 승인 회원 목록, 참여 캐릭터, 병종 슬롯, 날짜별 FULL/PARTIAL/ABSENT.
권한: 승인 회원, 운영 관리자, ADMIN; 미승인 신청자에게 타인 참여 상세 비노출.
검증: 연맹 전용이면 현재 연맹 자격 재확인.

[PT-004 참여 캐릭터·병종 관리]
목적: 승인 회원의 참여 캐릭터 추가/교체/제외 및 병종 지정.
표시: 본인 보유 캐릭터, 해당 파티 참여 상태, 재승인 대기, 병종 슬롯 1·2.
버튼: 캐릭터 추가, 본인 제외, 재등록 요청, 병종 저장; 관리자에게 제외/재승인 처리 버튼 노출.
검증: 승인 회원만 등록; 동일 파티 캐릭터 중복 금지; 관리자 제외 후 재등록은 PENDING_REAPPROVAL; 본인 제외 후 즉시 재등록.
병종 0~2개, 동일 병종 중복 불가. 병종 편집은 소유 회원/ADMIN만.
제외/교체 시 해당 파티 병종·일정 삭제. 생성자 마지막 캐릭터 제외 불가.

[PT-005 캐릭터별 전쟁 일정]
목적: 참여 캐릭터의 12일 일정 편집.
구성: 캐릭터 선택, 출발일 포함 12일 날짜표, 날짜별 FULL/PARTIAL/ABSENT 선택, 메모.
버튼: 날짜 저장, 초기화(FULL로 되돌림), 여러 날짜 일괄 적용(제안).
검증: PARTIAL 메모 필수, ABSENT 메모 선택, FULL은 행 삭제; 과거·미래 수정 가능.
권한: 편집은 소유 회원/ADMIN, 조회는 승인 파티 회원(연맹 전용은 연맹 자격 포함).
안내: 전쟁 시간 매일 KST 20:00~24:00, PARTIAL에는 별도 시간 입력 없음.

[PT-006 파티 공지]
목적: 파티 내부 공지 열람 및 운영 공지 관리.
표시: 상단 고정 공지, 일반 공지, 제목/본문/작성 시각.
버튼: 작성, 수정, 삭제, 고정/해제(생성자·추가 관리자·ADMIN).
권한: 승인 회원 조회, 운영 관리자 전체 공지 관리.
제한: 첨부 없음, 읽음 확인 없음.

[PT-007 파티 운영 관리]
목적: 신청 처리·회원 강퇴·차단 해제·캐릭터 재승인·추가 관리자 관리.
탭: 신청 대기/전체 회원/강퇴 차단/재승인 대기/관리자 관리.
버튼: 승인, 반려, 강퇴, 강퇴 차단 해제, 개별 캐릭터 제외, 캐릭터 재승인, 추가 관리자 지정·해제.
권한: 생성자·추가 관리자·ADMIN; 추가 관리자는 다른 관리자 강퇴·지정·해제 불가.
생성자 강퇴는 누구도 불가. 캐릭터 재승인 처리 권한은 운영 관리자에게 부여하는 설계 제안(최종 확인 필요).

[PT-008 내 파티]
목적: 내가 생성/신청/참여한 파티와 해체 상태 확인.
표시: 파티명, 내 신청/승인 상태, 출발일, 해체 여부, 관리자 여부.
필터(제안): 참여 중/신청 중/과거/해체.
버튼: 상세 이동, 참여 캐릭터 관리, 일정 관리.
주의: 탈퇴·강퇴 후 내 목록 유지 범위는 18장 미확정 사항 참조.

[AL-001 연맹 목록 / AL-002 연맹 생성]
목적: 활성 연맹 검색·가입 및 신규 연맹 생성.
목록: 연맹명, 가입 상태, 내 연맹 여부. 검색(제안): 연맹명.
생성 입력: 연맹명(필수). 생성자 자동 OWNER.
검증: 활성 연맹명 중복 금지, 해체된 이름 재사용 가능, 복수 창설/가입 가능.

[AL-003 연맹 상세 / AL-003-A 기본 정보·가입]
목적: 연맹 기본 정보 확인 및 회원 단위 가입 신청.
표시: 연맹명, 연맹장, 현재 내 가입 상태, 해체 상태.
버튼: 가입 신청, 신청 취소(대기), 탈퇴(일반 회원/부연맹장), 운영 관리 이동.
검증: 강퇴 차단 시 재신청 불가, 자발적 탈퇴 후 재승인 필요, 연맹장은 위임 또는 해체 전 탈퇴 불가.

[AL-003-B 연맹원]
목적: 현재 승인 연맹원과 등급 조회.
표시: OWNER/DEPUTY/MEMBER, 대표 캐릭터명.
권한: 현재 승인 연맹원만 상세 조회(제안).

[AL-004 연맹 공지]
목적: 연맹 공지 열람·관리.
표시: 제목, 본문, 고정 여부, 작성 시각.
버튼: 작성/수정/삭제/고정(OWNER·DEPUTY·ADMIN).
권한: 승인 연맹원만 조회. 첨부·읽음 추적 없음.

[AL-005 연맹 운영 관리]
목적: 가입 승인/반려, 회원 강퇴·차단 해제, 부연맹장 지정/해제, 연맹 해체.
탭: 가입 대기/회원 관리/차단 회원/공지 관리.
OWNER: 일반 회원·부연맹장 관리, 차단 해제, 위임, 해체.
DEPUTY: 가입 승인/반려 및 공지 관리; 다른 DEPUTY 강퇴/등급 변경 불가.
ADMIN: 시스템 운영 예외 권한.
연맹 해체 시 연결된 전용 파티 모두 해체.

[AL-006 연맹장 위임]
목적: 위임 요청·수락·거절·취소.
OWNER 입력: 위임 대상 현재 승인 회원, 위임 후 본인 등급(MEMBER/DEPUTY).
대상 회원: 수락/거절. OWNER: 대기 요청 취소.
검증: 연맹당 PENDING 1건; 수락 시 소유권·등급 원자적 변경.

[AL-007 내 연맹]
목적: 가입/생성/해체된 연맹과 현재 등급 확인.
표시: 연맹명, 가입 상태, OWNER/DEPUTY/MEMBER, 해체 여부.
버튼: 상세 이동, 운영 관리(권한 보유 시).

[RC-001 공통 랭크 달력]
목적: ADMIN이 수동 입력한 공통 랭크 시작일 안내.
표시: 월별 달력, 랭크 시작일 강조, 선택 날짜 상세.
권한: 조회는 공개 가능하도록 제안; 등록/수정/삭제는 ADMIN 전용.
주의: 파티 출발일과 독립; 자동 3일 주기 생성 없음.

[AD-001 운영 관리 / AD-002 공통 랭크 일정 관리]
목적: 시스템 ADMIN 운영 기능 진입 및 랭크 날짜 관리.
AD-002 입력: 랭크 시작일(필수), 제목(선택).
버튼: 등록, 수정, 삭제.
검증: ADMIN 역할 서버 확인, 날짜 중복 처리 정책은 DDL 전 확정.
기타 파티/연맹 관리 권한은 해당 상세 운영 화면을 재사용하는 방향 제안.

17. 화면 이동 관계·상태별 버튼/노출 규칙·개발 검증

[주요 이동 경로]
AU-001 -> AU-002(신규) / HM-001(기존)
HM-001 -> PT-008 / AL-007 / RC-001 / MY-002
PT-001 -> PT-002(생성) / PT-003(목록 선택)
PT-008 -> PT-003 -> PT-003-B / PT-004 / PT-005 / PT-006 / PT-007(권한 보유)
AL-001 -> AL-002(생성) / AL-003(선택)
AL-007 -> AL-003 -> AL-003-B / AL-004 / AL-005(권한 보유) / AL-006(위임 대상/OWNER)
RC-001 -> AD-002(ADMIN 편집 버튼)
MY-001 -> MY-002 / MY-003

[파티 상세 상태별 주 행동 버튼]
- 비로그인: 로그인 안내; 신청 버튼은 로그인 유도.
- 회원 신청 이력 없음 + 마감 전 + 자격 충족: '파티 신청'.
- PENDING: '신청 대기', '신청 취소'(정책상 허용 가능한 대기 취소).
- REJECTED/CANCELED/LEFT + 마감 전: '재신청'.
- APPROVED: '참여 캐릭터 관리', '전쟁 일정', '공지', '탈퇴'(생성자 제외).
- KICKED/BLOCKED: '강퇴로 신청 불가'; 차단 해제 이후 마감 전 '재신청'.
- 마감 후 비승인 회원: 신규/재신청 버튼 비활성, 사유 표시.
- DISSOLVED: 조회 가능한 과거 회원에게 읽기 전용; 신청/변경 불가.
- 출발일 경과만으로 승인 회원의 캐릭터/병종/일정 편집을 차단하지 않음.

[참여 캐릭터 상태별 주 행동 버튼]
- APPROVED: '병종 설정', '일정 설정', '본인 제외'(소유자), '관리자 제외'(운영 관리자).
- REMOVED_BY_USER: '즉시 재등록'(소유자).
- EXCLUDED_BY_ADMIN: '재등록 요청'(소유자).
- PENDING_REAPPROVAL: '승인 대기'(소유자), '승인/거절'(운영 관리자: 권한 최종 확정 필요).
- 생성자의 마지막 APPROVED 캐릭터: 제외 버튼 비활성 + 사유 안내.
- 회원 승인 취소/탈퇴/강퇴 상태: 캐릭터 등록/병종/일정 편집 불가.

[연맹 상태별 주 행동 버튼]
- 비회원: '가입 신청' (강퇴 차단 여부 검증).
- PENDING: '가입 대기', '신청 취소'(제안).
- APPROVED MEMBER: '연맹원', '공지', '탈퇴', '전용 파티'.
- APPROVED DEPUTY: 위 기능 + '가입 승인/반려', '공지 관리'.
- OWNER: 위 기능 + '등급/강퇴 관리', '연맹장 위임', '연맹 해체'.
- KICKED/BLOCKED: 차단 해제 전 신청 불가.
- DISSOLVED: 이전 참여자에게 읽기 전용 해체 상태 표시.

[공통 화면 처리 원칙]
1. API 응답에서 권한/상태를 판정하며, 프런트에서 숨긴 버튼만으로 보안 처리하지 않음.
2. 신청/승인/강퇴/재승인/위임은 처리 성공 후 최신 상태를 재조회.
3. 서버 오류는 인증 만료, 권한 없음, 마감 초과, 이미 처리됨, 중복 데이터로 구분하여 안내.
4. 삭제/강퇴/해체/탈퇴는 확인 다이얼로그 및 영향 범위(참여 캐릭터·병종·일정 삭제 등) 명시.
5. 날짜는 사용자에게 한국시간으로 표시. 전쟁 24:00 표기는 해당 날짜의 종료 경계임을 안내.
6. 페이지네이션·정렬·검색 조건은 조회 API와 합의하여 확정. 인원 상한은 두지 않음.
7. 연맹 전용 파티의 신청/승인/캐릭터 추가/일정 조회 시 현재 연맹 소속 재검증.
8. 계정 탈퇴 후 비개인 기록만 남도록 개인정보·공지 작성자 표시 규칙 일치 검증.

[개발 수용 시나리오]
AC-01 신규 회원이 UID 중복 없이 첫 캐릭터 등록 후 홈에 진입한다.
AC-02 생성자가 1개 캐릭터로 파티를 생성하고 마지막 캐릭터 제외가 거절된다.
AC-03 신청자는 캐릭터 선택 없이 신청하고 승인 후 0~N개 캐릭터를 등록한다.
AC-04 출발일이 지난 파티는 목록에 없지만 직접 링크에서 마감 전 신청할 수 있다.
AC-05 마감 후 신규 신청은 거절되지만 기존 PENDING은 승인할 수 있다.
AC-06 관리자가 제외한 캐릭터는 재승인 전 병종/일정 편집이 불가능하다.
AC-07 본인이 제외한 캐릭터는 즉시 재등록되고 이전 병종/일정은 복구되지 않는다.
AC-08 동일 캐릭터가 두 파티에 참여해도 병종/일정이 서로 영향을 주지 않는다.
AC-09 연맹 탈퇴자가 전용 파티 생성자이면 해당 파티가 자동 해체된다.
AC-10 연맹장 위임 요청은 연맹당 하나만 대기하며 수락 시 역할이 일괄 변경된다.
AC-11 해체 파티/연맹은 공개 목록에서 제외되고 기존 참여자 내 목록에는 해체로 표시된다.
AC-12 계정 탈퇴 전 소유 파티·연맹 정리 여부를 확인하고 개인정보 처리 정책을 따른다.

[미확정 UI/운영 선택지 - 확정 정책과 구분]
- 공개 화면의 비로그인 조회 범위 및 연맹 전용 파티 검색 노출 방식.
- 신청 대기 취소/연맹 가입 대기 취소 버튼의 구체적인 허용 조건.
- 관리자 제외 캐릭터의 재승인 거절 권한과 거절 후 상태, 관리자별 처리 범위.
- 탈퇴/강퇴 이력이 있는 회원의 '내 파티/내 연맹' 표시 범위.
- 홈 요약 카드·검색 필터·일괄 일정 입력·모바일 반응형 화면 상세.
- 최종 디자인 시안, 접근성, 오류 메시지 문구, 입력 최대 길이.

============================================================================
18. 물리 DB 설계 전 남은 명세/결정
============================================================================
[정책이 아니라 구현 상세로 확정할 항목]
1) 마감 시각 경계: KST 비교, 정확히 마감 시각과 동일한 요청 허용 여부, 생성 시 과거 마감 허용 여부, 타임존 저장 방식.
2) 참여 캐릭터 재등록: 관리자 제외 후 재승인 거절 시 상태 전이 및 기존 행 재사용 방식, 관리자 승인 담당 권한(기본적으로 파티 생성자·추가 관리자·ADMIN을 제안).
3) 신청/참여 동시성: 같은 회원·캐릭터의 중복 INSERT 방지, OWNER 마지막 캐릭터 제거 방지, 연맹 탈퇴와 파티 신청 경쟁 상태에 대한 잠금 순서.
4) 탈퇴/해체 후 '기존 참여자' 조회 범위: LEFT/KICKED 회원의 내 목록 표시 여부와 익명화된 과거 관계의 조회 권한.
5) 계정 탈퇴 시 데이터별 보존/삭제·비식별화 방식, 보존 기간, 인증 제공자 계정 삭제와 재가입 처리. 법률·개인정보 처리방침 검토 필요.
6) 파티 생성 직후 마감 시각을 출발일 이후로 설정할 수 있으므로, 출발일과 마감일의 선후 제약을 DB에 강제하지 않음.
7) 신청 마감 이후 캐릭터 추가·교체는 허용. 단 승인 회원 자격 및 연맹 자격을 반드시 확인.
8) 활성 연맹명 비교 규칙(공백, 대소문자, 유니코드 정규화), 병종 코드 마스터 목록, 컬럼 길이, 삭제 상태 코드, 인덱스 및 시퀀스 네이밍.
9) 파티 생성자의 계정 탈퇴/캐릭터 삭제/연맹 탈퇴에 대한 선행 처리 및 실패 복구.

[중요한 구분]
- 본 문서는 '논리 설계 착수 가능한 수준'의 통합 설계서이다. 원본 v4.0과 달리 확정 정책을 우선 반영하였으나 물리 DDL, 최종 코드표, 화면 상세 와이어프레임, 개인정보 보존기간까지 확정된 것은 아니다.
- 추가 관리자가 관리자 제외 캐릭터의 재승인을 처리할 수 있는지는 기존 운영 권한을 근거로 한 설계 제안이며 명시 정책 확정은 필요하다.
- 회원이 직접 참여 캐릭터를 바꾸는 경우 기존 참여 행의 제거/재등록 처리와 관리자에 의한 제외는 별도로 구분한다.

설계 기준 우선순위: 사용자 명시 후속 확정 정책이 선행 충돌 정책보다 우선. 미확정 구현 제안은 확정 정책으로 간주하지 않음.

[문서 끝]
