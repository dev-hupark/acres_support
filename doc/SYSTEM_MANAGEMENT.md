# 시스템 관리 · 병종 관리

시스템 ADMIN만 사이드바/대시보드의 시스템 관리 메뉴와 하위 병종 관리 메뉴를 볼 수 있습니다. 일반 회원은 직접 URL로 접근해도 차단됩니다. DB는 현재 업무 회원의 ROLE을 조회하며 파티 생성자/추가 관리자 권한만으로 시스템 병종 관리 RPC를 실행할 수 없습니다.

## 병종 정보

기존 `acres_troops` 테이블을 확장했습니다. 기존 code PK와 파티 참여 캐릭터의 병종 FK를 유지합니다.

| 표시 | 컬럼 | 입력 |
| --- | --- | --- |
| 병종명 | name | 필수, 최대 60자 |
| 구분 | category | 공통코드 선택 필수 |
| 체력 | health | 선택, 0 이상 소수점 3자리 |
| 분노 | rage | 선택, 자유 텍스트 (예: `0`, `4/6`), 형식 검사 없음 |
| 이동거리 | movement | 선택, 0 이상 소수점 3자리 |
| 공격력 | attack | 선택, 자유 텍스트 (예: `100~150`) |
| 사거리 | attack_range | 선택, 0 이상 소수점 3자리 |
| 식량소비 | food_consumption | 선택, 0 이상 소수점 3자리 |

미입력 능력치는 NULL로 보존하며 화면에는 `—`로 표시합니다. 단위는 아직 확정하지 않아 고정 표기하지 않습니다. code는 서버에서 생성합니다. 상태(ACTIVE/INACTIVE) 및 생성·수정 일시를 함께 저장합니다. 이번 화면은 등록·조회·검색·활성/비활성 전환을 제공하며 스킬은 추가하지 않았습니다.

2026-11-10: 개발용 Supabase에 직접 변경을 적용했습니다. rage와 attack 컬럼 및 등록 RPC 인자를 text로 변경했고, 분노/공격력의 형식 검사를 제거했습니다. `0`, `4/6`, 범위 표현 등을 그대로 저장하며 미입력은 NULL입니다. 기존 숫자는 문자열로 보존하고 나머지 능력치는 숫자형을 유지합니다. 이전 인자 타입의 RPC 오버로드는 제거해 API 호출이 중복 해석되지 않도록 했습니다.

## 공통코드

기존 서비스 테이블에는 전용 공통코드 테이블이 없었습니다. 사용자 확인 후 다음 테이블을 추가했습니다.

- `acres_code_groups`: 코드그룹 키와 이름
- `acres_common_codes`: 그룹별 코드·이름·정렬순서·활성 상태, `(group_code, code)` 복합 PK

`TROOP_CATEGORY` 그룹에 다음 5개 코드를 등록했습니다.

| 코드 | 이름 |
| --- | --- |
| SHIELD | 방패병 |
| ARCHER | 궁병 |
| SPEAR | 창병 |
| CAVALRY | 기병 |
| SIEGE | 병기 |

병종은 `category_group='TROOP_CATEGORY'`와 `category`의 복합 FK로 해당 코드를 참조합니다. 기존 병종의 구분/능력치는 임의 추정하지 않고 NULL로 유지하며, 신규 등록에서는 활성 구분을 선택해야 합니다. 공통코드 관리 화면은 이번 범위에 포함하지 않았습니다.

## 활성·비활성

사용자 후속 확인에 따라 물리 삭제 기능은 제공하지 않습니다. 비활성화 시 기존 파티의 병종 선택과 표시 이름을 보존하며, 신규 선택 목록에서는 제외합니다. 이미 선택된 비활성 병종은 비활성 표기와 함께 보여 주고 기존 값을 유지한 저장은 허용합니다. 해제한 뒤 다시 선택하는 것은 차단하며, 재활성화하면 다시 선택할 수 있습니다. 이 검증은 화면과 DB에 모두 적용합니다.

파티 변경은 파티 행을 잠그고 선택할 병종 행에 공유 잠금을 잡습니다. 활성 상태 변경은 해당 병종 행에 배타 잠금을 잡아 동시 비활성화/선택 경쟁을 처리합니다.

## 적용 및 검증

개발용 Supabase에 적용 완료했습니다. 코드 테이블 2개와 병종 구분 5개를 추가하고 병종 테이블을 확장했으며, 기존 병종 행은 보존했습니다. 사용자 요청에 따라 적용 SQL 파일은 보관하지 않으며 별도 요청 시에만 생성합니다.

추가 RPC: `acres_admin_troop_list`, `acres_admin_troop_create`, `acres_admin_troop_status`. 병종 선택 RPC `acres_participation_save`에는 비활성 신규 선택 차단을 반영했습니다. 브라우저에서 공통코드/병종을 직접 변경할 수 없으며 ADMIN RPC로만 병종을 변경합니다.

React 테스트 25개, 로컬 DB 통합 검증 94개, `CI=true` 프로덕션 빌드 통과. 실제 DB의 컬럼 타입/코드/RPC 권한 및 데이터 보존을 확인했습니다. 실제 로그인 브라우저를 통한 ADMIN 작업은 별도 확인이 필요합니다.
