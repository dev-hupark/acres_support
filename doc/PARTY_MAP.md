# 파티 맵 관리

2026-11-09 후속 요구사항과 확인 답변을 반영한 추가 설계입니다. 기존 3개 설계/리뷰 문서는 보존했습니다. 참고 프로젝트 `acres_map`은 화면 형태만 참고했으며, 로컬 저장이나 좌상단 원점 구현은 사용하지 않습니다.

## 좌표와 표시

- 논리 좌표는 정수 X/Y 각각 **0~600, 양끝 포함**입니다. 두 끝을 포함하므로 각 축에는 601개의 좌표 칸이 있습니다. 논리 좌표 600의 의미를 유지하고 SVG에도 601칸을 배치합니다.
- 원점 `(0,0)`은 좌하단, `(600,600)`은 우상단입니다. X는 오른쪽, Y는 위로 증가합니다.
- 기타는 입력 좌표 1칸을 차지합니다. 시작 좌표 0~600.
- 나머지 세력은 `(x,y)`, `(x+1,y)`, `(x,y+1)`, `(x+1,y+1)`을 차지합니다. 지도 범위를 벗어나지 않도록 시작 좌표 0~599.
- 아군 초록, 적군 빨강, 동맹군 보라, 중립 노랑, 기타 주황. 사망 여부 Y는 세력과 무관하게 회색입니다. 사망 항목도 원래 면적을 점유합니다.
- 점유 칸이 하나라도 겹치면 등록/수정을 거부합니다. 삭제는 논리 삭제이며 삭제된 항목은 더 이상 칸을 점유하지 않습니다. 별칭 자체는 중복 허용합니다.
- 지도는 좌표 1칸당 약 1.3px(지도 약 781px)입니다. 확대/축소·위치 이동과 지도 내부 스크롤은 제거했습니다. 좁은 화면에서는 지도를 비례 축소하되 마커는 화면상 지름 약 12px의 원으로 유지합니다. 2×2 항목은 네 칸의 중심, 기타는 한 칸의 중심에 배치합니다. 지도 가장자리에 작은 여백을 두어 경계 마커가 잘리지 않게 했습니다. 확대된 표시가 겹쳐 보여도 실제 점유·중복 검사는 기존 1×1/2×2 좌표 기준을 유지합니다.
- SVG로 격자를 그리므로 601×601개의 HTML 요소를 생성하지 않습니다. Y축은 렌더링/마우스 좌표 변환에서만 뒤집고 DB에는 실제 논리 좌표를 저장합니다.

## 권한과 동시 수정

- 파티 상세 탭 순서: 기본 정보 → 참여 현황 → 캐릭터·일정 → 파티 공지 → **맵 관리** → 운영 관리.
- 현재 승인된 파티원은 작성자와 관계없이 모든 항목을 조회/등록/수정/삭제할 수 있습니다. 참여 캐릭터가 0개여도 회원 승인 상태이면 가능합니다.
- 비로그인·미승인·탈퇴·강퇴 회원은 맵 조회와 변경이 불가능합니다. 기존 시스템 ADMIN 예외 권한을 유지합니다.
- 해체한 파티는 조회만 가능합니다. 모집 마감과 맵 변경 권한은 별개입니다.
- 모든 맵 변경 RPC가 파티 행을 잠근 뒤 현재 권한·활성 상태·점유 칸을 다시 확인합니다. 동시 등록도 같은 잠금 규칙으로 중복 점유를 차단합니다.
- 수정/삭제에 읽은 version을 전송하며 현재 값과 다르면 충돌로 거부합니다. 오류 시 입력을 보존하고, 새로 조회한 목록의 항목을 다시 선택해서 최신 버전을 확인할 수 있습니다.
- 20초 주기와 창 복귀 시 재조회합니다. 초 단위 실시간 구독 방식은 아닙니다. 조회 실패 시 지도 데이터는 숨기고 변경을 비활성화합니다.

## 새 테이블

`public.acres_party_map_entries`

| 컬럼 | 타입 | 용도 |
| --- | --- | --- |
| id | uuid PK | 항목 식별 |
| party_id | uuid FK | acres_parties.id |
| alias | text | 별칭, 1~80자 |
| x / y | integer | 논리 좌표 |
| memo | text | 선택 메모, 최대 2000자 |
| is_dead | char(1) | Y 또는 N |
| faction | text | FRIENDLY / ENEMY / ALLIANCE / NEUTRAL / OTHER |
| status | text | ACTIVE / DELETED |
| version | integer | 동시 수정 충돌 확인, 최초 1 |
| created_at / updated_at | timestamptz | 생성/수정 일시 |

추가 컬럼과 전체 승인 회원의 수정·삭제 권한, 경계 좌표·중복 점유 차단은 사용자 확인을 받았습니다. 별도의 작성자 소유권이나 업무 변경 이력 테이블은 추가하지 않았습니다.

## 마이그레이션

`supabase/migrations/202611090002_party_map.sql`

신규 테이블 1개, 인덱스, RLS, 다음 RPC와 실행 권한을 추가합니다. 기존 테이블 데이터 및 기존 RPC는 변경하지 않습니다.

- `acres_map_list(p_party)`
- `acres_map_save(p_party,p_alias,p_x,p_y,p_memo,p_is_dead,p_faction,p_id,p_version)`
- `acres_map_delete(p_party,p_id,p_version)`

브라우저의 직접 테이블 조회/변경은 허용하지 않고 RPC에서 권한을 검증합니다. 신규 설치는 초기 마이그레이션 후 맵 마이그레이션 순서로 적용합니다. 기존 초기 설치가 완료된 프로젝트에는 맵 마이그레이션만 적용하며, 이미 적용된 파일을 다시 실행하지 않습니다.

`scripts/db-client.cjs`는 개발 도구용 Node DB 연결 모듈입니다. `.env.local`의 SUPABASE_DB_URL을 사용하고 Supabase CA를 HTTPS로 받아 호스트·인증서를 검증합니다. 프런트엔드에서는 사용하지 않습니다. CRA 빌드 호환성을 위해 TypeScript 4.9.5를 명시했습니다.

검증 명령: `npm.cmd test -- --watchAll=false --runInBand`, `npm.cmd run test:db`, `npm.cmd run build`.

## 적용 결과 (2026-11-09)

실제 Supabase DB에 `202611090002_party_map.sql`을 적용했습니다. 신규 테이블 1개(12컬럼), RLS, RPC 3개, authenticated 실행 허용 및 anon 실행 차단을 확인했습니다. 브라우저의 직접 INSERT/UPDATE 권한은 없습니다. 사용자 식별정보가 없는 authenticated 호출도 거부됩니다. 기존 파티 데이터는 변경하지 않았습니다.

검증 결과: React/좌표 테스트 19개, 로컬 PostgreSQL 통합 검증 67개, 프로덕션 빌드 통과. 실제 로그인 사용자 간 브라우저 공동 편집은 자동 검증 범위에 포함하지 않았습니다.
